# UX Audit Fix Plan — Sentinel Frontend

## Overview

Fix 71 UX audit findings (12 Critical, 24 High, 24 Medium, 11 Low) across 4 phases. The audit is at `ux-product-audit.md`. The plan prioritizes trust/safety first, then core flows, accessibility, and finally visual consistency.

**Key constraint**: Build shared design system components first — many fixes depend on them.

---

## Phase 1: Design System Foundation + Trust/Safety (P0)

> Establish shared components, then fix the most damaging trust issues.

### Step 1.1 — Create `src/components/ui/` directory with shared components

**New files:**
- `src/components/ui/Modal.tsx` — Accessible modal base (focus trap, `aria-modal`, `aria-labelledby`, Escape key, backdrop). Use `useFocusTrap` hook. Props: `isOpen`, `onClose`, `title`, `children`, `size?`. Replace 5 inconsistent modal implementations with this base.
- `src/components/ui/Badge.tsx` — Unified status/severity badge. Props: `variant` (success/danger/warning/info/purple), `icon?`, `dot?`, `children`. Replaces inline `getStatusBadge()` functions duplicated in DashboardPage, ScanHistoryPage, etc.
- `src/components/ui/StatusBadge.tsx` — Scan-status-specific badge wrapping Badge with the scan state → color mapping.
- `src/components/ui/IconButton.tsx` — Touch-target-compliant icon button. Min 44px touch target. Props: `icon`, `label`, `variant?`, `size?`, `onClick`. Replaces tiny table action buttons (audit ID-05).
- `src/components/ui/HelpTooltip.tsx` — Inline help icon with tooltip. Props: `content: string`, `position?`. For contextual help (audit UX-09).
- `src/components/ui/ProgressBar.tsx` — Generic progress bar. Props: `value`, `max`, `label?`, `estimatedTime?`. For scan progress (audit ID-02).
- `src/components/ui/SkipLink.tsx` — Skip-to-main-content link. For accessibility (audit A11Y-05).

**Modified files:**
- `src/components/ConfirmModal.tsx` — Refactor to use `Modal` base internally. Keep existing props API.
- `src/components/ScanErrorModal.tsx` — Refactor to use `Modal` base + `useFocusTrap`. Remove manual focus trap code.
- `src/components/FindingDetailModal.tsx` — Refactor to use `Modal` base.
- `src/components/IssueDetailModal.tsx` — Refactor to use `Modal` base.
- `src/components/RescanRequestModal.tsx` — Refactor to use `Modal` base.

**Inline modals to replace:**
- `src/pages/ScanStatusPage.tsx` lines 339-362 — Replace inline cancel modal with `ConfirmModal`.
- `src/pages/ScanHistoryPage.tsx` lines 167-190 — Replace inline force-stop modal with `ConfirmModal`.
- `src/pages/UserManagementPage.tsx` lines 245-355 — Replace 3 inline modals with `ConfirmModal` or `Modal` base.

### Step 1.2 — Structured Error Display (TR-01)

**Modified files:**

- `src/pages/UserManagementPage.tsx` — Replace toast-only errors with `ErrorDisplay` where appropriate.

### Step 1.3 — Destructive Action Confirmations (TR-02)

**Modified files:**
- `src/pages/DashboardPage.tsx` — Update delete-project `ConfirmModal` message to include consequences: number of scans that will be lost, orphaned scan info.
- `src/pages/ScanStatusPage.tsx` — Update cancel-scan confirmation to explain: "Partial results will be lost. You'll need to re-trigger the scan from the project page."

### Step 1.4 — Real System Health Status (TR-03)

**New file:**
- `src/hooks/useHealthStatus.ts` — Polls `/api/v1/health` every 60s. Returns `{ status: 'operational' | 'degraded' | 'down', details?: string }`.

**Modified files:**
- `src/components/Layout.tsx` — Replace hardcoded "System Operational" green dot (line 218-222) with health status from `useHealthStatus`. Show green/amber/red based on actual status.
- `src/services/api.ts` — Add `api.health.check()` method.

### Step 2.5 — Dashboard Empty State + Primary Action (UX-03)

**Modified files:**

### Step 2.6 — Create Project Form Improvements (UX-04)

**Modified files:**

- `src/pages/IssuesTriagePage.tsx` — Replace inline empty states (lines 272-281) with `<EmptyState>`.

### Step 4.2 — Button Style Enforcement (UI-01)

**Modified files:**
- All pages using inline button markup — Migrate to shared `Button` component from `src/components/Button.tsx`. Key files: `DashboardPage.tsx`, `CreateProjectPage.tsx`, `ScanStatusPage.tsx`, `UserManagementPage.tsx`, `ProjectControlPage.tsx`.

### Step 4.3 — Border-Radius Standardization (UI-02)

**Modified files:**
- `src/components/ConfirmModal.tsx` — Change `rounded-[3.5rem]` to `rounded-2xl` and `rounded-[2.5rem]` to `rounded-xl`.
- `src/components/ScanErrorModal.tsx` — Same radius cleanup.
- `src/components/FindingDetailModal.tsx` — Same.
- `src/components/IssueDetailModal.tsx` — Same.
- `src/components/RescanRequestModal.tsx` — Same.
- All pages with `rounded-[3.5rem]`, `rounded-[2.5rem]`, `rounded-[2rem]` — Replace with the 4-tier system: `rounded-sm` (inputs), `rounded-md` (buttons/badges), `rounded-lg` (cards), `rounded-xl` (modals).

### Step 4.4 — Status Badge Color Fix (UI-03)

**Modified files:**
- `src/pages/DashboardPage.tsx` — Change amber badges from `bg-amber-50 text-amber-700` to `bg-amber-100 text-amber-800` (contrast 6.5:1).
- `src/pages/ProjectControlPage.tsx` — Same fix.
- `src/pages/ScanHistoryPage.tsx` — Same fix.

### Step 4.5 — Consistent Error Handling (CON-01 related)

Already addressed in Step 1.2 by standardizing on `ErrorDisplay` component.

### Step 4.6 — Terminology Guide (CON-02)

No code changes — this is documentation. Add a `docs/TERMINOLOGY.md` file defining: Project, Scan, Finding, Issue, Verification.

## Verification

After each phase:
1. `npm run lint` — No ESLint errors
2. `npm run build` — TypeScript compiles cleanly (`tsc -b` runs as part of build)
3. `npx vitest run` — All existing tests pass
4. Manual check: visit `http://localhost:5173`, login with `admin`/`admin123`, verify:
   - Modals open/close with Escape and focus trap works
   - Error states show structured messages with retry buttons
   - Empty states use consistent component
   - Dashboard shows onboarding for first-time visitors
   - "Rescan Approvals" page has contextual explanation
   - System status indicator reflects actual health
   - Status badges have sufficient contrast
   - Skip link appears on Tab from address bar

Run full lint+build+test suite at the end:
```bash
npm run lint && npm run build && npx vitest run
```
