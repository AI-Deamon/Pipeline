# Implementation Plan: Deep Code Audit and Bug Analysis

**Branch**: `001-deep-code-audit` | **Date**: 2026-05-22 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `/specs/001-deep-code-audit/spec.md`

## Summary

Deep audit and systematic fix of 129 issues across the Sentinel DevSecOps platform, organized into 5 phases: Security Critical (13 tasks), Authentication & Session (11 tasks), Async/State/Cache (12 tasks), UI/UX & Accessibility (14 tasks), and Testing & Verification (8 tasks). All fixes grounded in actual code analysis with exact file/line references.

## Technical Context

**Language/Version**: Python 3.11 (backend), TypeScript 5.x (frontend)

**Primary Dependencies**: FastAPI, SQLAlchemy, Celery + Redis (backend); React 19, TanStack Query, Vite (frontend)

**Storage**: PostgreSQL (persistent data), Redis (Celery broker/cache), sessionStorage (frontend tokens)

**Testing**: pytest + TestClient (backend); Vitest + jsdom (frontend)

**Target Platform**: Linux server, Docker Compose with host networking

**Project Type**: Web application (React SPA + FastAPI REST API + WebSocket)

**Performance Goals**: <200ms p95 API response, <3s scan status update latency, zero unhandled promise rejections

**Constraints**: JWT 7-day expiry, one active scan per project (DB constraint `ix_scans_project_state`), WCAG 2.1 AA for modals, no secrets in client bundles

**Scale/Scope**: Single-tenant DevSecOps platform, ~50 React components, ~30 FastAPI endpoints, 6 modals, 5 pages with complex async state

## Complexity Tracking

| Violation | Why Needed | Simpler Alternative Rejected Because |
|-----------|------------|-------------------------------------|
| `user_id` FK on `ProjectDB` | User-level data isolation (FR-015) | Row-level security in PostgreSQL adds DB complexity; application-level filtering is standard for this scale |
| `useFocusTrap` hook | 6 modals need identical WCAG 2.1 AA behavior | Per-modal inline implementation duplicates code 6 times, risk of inconsistency |
| `ErrorBoundary` class component | Catch render errors and chunk-loading failures | `react-error-boundary` library adds unnecessary dependency; class component is ~40 lines |
| `SELECT FOR UPDATE` for scan creation | Prevent race condition on duplicate active scans | Application-level lock (Redis) adds complexity; DB-level atomicity is simpler and more reliable |
