# Plan: Implement Reporting Feature from Jenkins Stages

## Problem Statement
The DevSecOps pipeline currently triggers Jenkins scans but does not properly handle the reports generated by Jenkins stages. We need to:
1. Capture reports generated by Jenkins stages during scanning
2. Store these reports in the database
3. Display the reports in the user dashboard
4. Allow users to view detailed findings from each security tool

## Current State Analysis
Based on code review:

### Backend Components:
- **Reports API** (`backend/app/api/reports.py`): Already exists with endpoints for getting reports and summaries
- **Jenkins Callback** (`backend/app/api/scans/callbacks.py`): Receives scan status from Jenkins but doesn't process reports
- **Report Tasks** (`backend/app/tasks/report_tasks.py`: Celery task that fetches and processes reports after scan completion
- **Report Fetcher** (`backend/app/services/reporting/fetcher.py`: Fetches artifacts from Jenkins and stores them as `ScanReportDB` records
- **Report Parsers** (`backend/app/services/reporting/parsers/`: Various parsers for different security tools

### Frontend Components:
- **Project Reports Page** (`src/pages/ProjectReportsPage.tsx`: Displays detailed reports for a project (already implemented)
- **Dashboard Page** (`src/pages/DashboardPage.tsx`: Shows project list with scan status but no report summary
- **API Service** (`src/services/api.ts`: Likely has methods for fetching reports

elif jenkins_status == "SUCCESS":
    scan_obj.state = ScanState.COMPLETED

    # Trigger async report processing
    build_num = str(build_number) if build_number else None
    if build_num:
        from app.tasks.report_tasks import process_scan_reports_task
        from app.core.config import settings

        background_tasks.add_task(
            process_scan_reports_task.delay,
            scan_id=scan_id,

## Risks and Mitigations
1. **Report fetching failures**: Mitigated by retry logic in Celery tasks
2. **Performance issues with large reports**: Mitigated by asynchronous processing
3. **Storage concerns**: Mitigated by expiration policies (90 days by default)
4. **Jenkins compatibility**: Mitigated by flexible artifact fetching

## Success Criteria
1. When a Jenkins scan completes successfully, reports are automatically fetched and stored
2. Dashboard shows severity summary for each project
3. Users can navigate to detailed reports page for each project
4. Detailed reports show findings broken down by tool and severity
5. Reports are properly cleaned up after expiration period
