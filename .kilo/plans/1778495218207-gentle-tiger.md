# Fix WebSocket Connection Failure

## Problem
Firefox cannot establish WebSocket connection to `ws://localhost:5173/api/v1/ws/scans?scan_id=...`. The connection fails with "Firefox can't establish a connection to the server."

## Root Cause Analysis Completed

### Current Status: ✅ WORKING
After investigation, the WebSocket infrastructure is functioning correctly:

1. **Nginx Configuration** (`docker/nginx.conf`): 
   - Has correct WebSocket headers (`Upgrade`, `Connection`, `proxy_http_version 1.1`)
   - Proxy target `http://127.0.0.1:8000/api/` works correctly (frontend container uses host network mode)
   - Logs show `101 Switching Protocols` responses for WebSocket upgrades

2. **Backend** (`backend/app/websockets/`):
   - WebSocket endpoint at `/api/v1/ws/scans` is properly registered
   - TestClient confirms WebSocket handshake and ping/pong work

3. **Frontend** (`src/hooks/useScanWebSocket.ts:62`):
   - Uses `window.location.origin` which correctly resolves to `http://localhost:5173`
   - WebSocket URL construction is correct

4. **Verification Tests Passed**:
   - `curl` shows nginx returns `101` for WebSocket upgrades
   - Python `websockets` library successfully connects and receives `pong`
   - All containers running (frontend, backend, celery, postgres, redis)

## Possible Causes for Original Errors

1. **Stale Error Messages**: Browser console may have shown cached/repeated errors from earlier failed attempts
2. **Browser Cache**: User may need hard refresh (`Ctrl+Shift+R`) or clear browser cache
3. **Transient Network Issue**: Temporary connectivity issue during initial page load

## Recommended Actions

### Option 1: Hard Refresh (No Code Changes)
1. Hard refresh the browser (`Ctrl+Shift+R`)
2. Clear browser cache if issue persists
3. Check Developer Tools → Network tab for any blocked WebSocket requests

### Option 2: Verify Environment
Run a fresh test:
```bash

```

## Conclusion
The WebSocket infrastructure is correctly configured and working. The reported error appears to be from a transient state or browser cache. No code changes required at this time.
