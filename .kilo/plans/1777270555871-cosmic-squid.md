# Plan to Fix Container Accessibility Issues

## Problem Analysis
Containers are building successfully but services are not accessible. The issue appears to be related to network configuration conflicts between docker-compose.yml (base) and docker-compose.staging.yml (staging override).

## Root Cause Hypothesis
The base docker-compose.yml sets `network_mode: host` for backend and celery_worker services, which causes port mappings defined in docker-compose.staging.yml to be ignored (as evidenced by the warning: "Published ports are discarded when using host network mode").

## Diagnostic Steps

### 1. Check Current Container State
- Verify which network mode each service is actually using
- Check actual port bindings vs expected bindings
- Examine container logs for startup errors

### 2. Verify Service Configuration
- Confirm what ports the backend application actually listens on (check Dockerfiles and app config)
- Verify frontend nginx configuration
- Check if health checks are passing for postgres/redis

### 3. Test Connectivity
- Try accessing services on expected ports based on actual network mode
- Test internal connectivity between services
- Verify environment variables are correctly passed

## Potential Solutions

### Option A: Modify Network Mode Configuration
Remove `network_mode: host` from base docker-compose.yml for backend and celery_worker, allowing port mappings in staging file to work.

### Option B: Update Staging Configuration to Match Host Mode
If host networking is required, adjust staging to:
- Remove port mappings (since they're ignored)
- Ensure applications bind to correct host ports
- Update frontend to access backend via localhost:8000 instead of localhost:5173/proxy

### Option C: Use Different Approach for Staging
Create a staging-specific network configuration that doesn't conflict with base settings.

## Recommended Approach
Option A is preferred because:
1. It maintains consistency between environments
2. Port mappings work as expected
3. Simpler troubleshooting
4. Matches typical docker-compose usage patterns

## Implementation Plan

### Step 1: Modify Base Docker Compose
Remove `network_mode: host` from backend and celery_worker services in docker-compose.yml

### Step 2: Verify Port Configurations
Confirm that:
- Backend exposes/binds to port 8000
- Frontend exposes/binds to port 80 (mapped to 5173)
- Environment variables reference correct service names and ports

### Step 3: Test the Fix
- Run `python run.py staging`
- Verify all containers show healthy status
- Test frontend accessibility at http://localhost:5173
- Test backend API accessibility at http://localhost:8000

### Step 4: Validate End-to-End Functionality
- Login with default credentials
- Trigger a test scan
- Verify scan results are accessible

## Rollback Plan
If issues persist, revert network mode changes and investigate alternative causes such as:
- Port conflicts on host machine
- Firewall restrictions
- Application binding to wrong interfaces (0.0.0.0 vs 127.0.0.1)
